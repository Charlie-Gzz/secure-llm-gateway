# Decisions

Format: `Decision | Options considered | Why I picked this | Easy to change? (yes/no)`

| Decision | Options considered | Why I picked this | Easy to change? |
|---|---|---|---|
| Product name: **Bulwark** | Bastion, Aegis, Sentinel, Warden, Moat | Short, memorable, literally means "a defensive wall"; fits the shield logo; less overused than Aegis/Sentinel in the LLM-security space | yes (string in config + logo SVG) |
| Default branch `main` | main, master | GitHub default | yes |
| Upstream defaults to `mock` | anthropic, mock | `GATEWAY_ANTHROPIC_API_KEY` was not set at build time (Section 1.2) | yes (`UPSTREAM` in `.env`) |
| Upstream model `claude-haiku-5-5` at $0.10 / $0.50 per 1M tokens, effort `low` | Haiku 4.5 ($1/$5), Sonnet 5.5 | Cheapest current Claude model per Anthropic's model table (checked Nov 2026). `low` effort keeps proxy latency/cost down. Model ID + prices live in `policy.yaml` | yes |
| Call Claude with the official `anthropic` SDK instead of raw httpx | httpx (plan's stack table), anthropic SDK | Anthropic's guidance is to use the official SDK (typed errors, retries); httpx is still used by tests and scripts. Note: anthropic 2.x is built on `httpx2` | yes |
| Don't forward `temperature` / `top_p` to Claude | forward them, drop them | Non-default sampling params return 400 on Haiku 5.5; dropping them keeps OpenAI clients that send `temperature` working | yes |
| Blocked requests return HTTP 200 with `finish_reason: "content_filter"` | 400/403 error, 200 + content_filter | Matches OpenAI's own behavior for filtered content, so unmodified clients don't crash; verdict is also in the `X-Gateway-Verdict` header and `gateway` field | yes |
| Mock upstream priced as Haiku (`mock-haiku`) and tokens estimated at ~4 chars/token | price at $0, real tokenizer | Keeps dashboards and cost math realistic offline without a tokenizer download | yes |
| Only `user` and `tool` message text is screened; `system`/`developer` prompts are trusted | screen everything | System prompts come from the app developer, not the end user; screening them would flag legit instructions like "ignore off-topic requests" | yes |
| OpenAI drop-in test uses a real uvicorn server on a free port | ASGI transport | openai 3.x uses `httpx2`, which can't share Starlette's httpx test client; a real socket is the more honest test anyway | yes |
| `make` on Windows via `mingw32-make` | install GNU make, PowerShell scripts | Already installed; Makefile is portable to macOS/Linux/devcontainer unchanged | yes |
| Classifier: `protectai/deberta-v3-base-prompt-injection-v2`, using the ONNX export shipped in its repo (Apache-2.0, not gated) | Export with optimum+torch; deepset fallback | Repo already publishes `onnx/model.onnx`; downloading it avoids a ~2 GB PyTorch install in dev and Docker. The optimum export path remains for the deepset fallback | yes |
| **Serve fp32, not int8.** Tried ONNX Runtime dynamic int8 quantization twice (default, and per-channel MatMul-only) | int8 (244–539 MB, ~21 ms) vs fp32 (739 MB, ~27 ms) | int8 destroyed accuracy: attacks scored ~0.05–0.15 and benign prompts up to 0.997. A ~20% latency gain is worthless if the model misses every attack. Lesson for the write-up: always re-evaluate after quantizing | yes |
| Classifier threshold 0.90 | 0.5, 0.8, 0.9, 0.95 | Model outputs are near-binary (most scores <0.05 or >0.95); 0.9 trims borderline false positives. Revisit after M4 eval | yes (`policy.yaml`) |
| Long prompts scored in 512-token windows (stride 128), max probability wins | truncate to 512 | Truncation would let an attacker hide the payload after 512 tokens of filler; covered by a test | yes |
| Presidio entities: SSN, credit card, email, phone, IBAN, passport, IP. **No PERSON** | include PERSON | spaCy PERSON would redact names in ordinary questions ("Who was Abraham Lincoln?"), breaking answers and inflating "redacted" verdicts | yes (`policy.yaml`) |
| PII `min_score` 0.4 | 0.5 (Presidio default-ish) | Presidio scores US phone numbers at 0.4 without strong context, so 0.5 missed "call 415-555-0132" | yes |
| spaCy `en_core_web_lg` pinned as a wheel URL in `pyproject.toml` | `spacy download` at setup time | `uv sync` removes packages that aren't in the lockfile, so a downloaded model would vanish on the next sync | yes |
| Rules guard tuned for precision; `no_restrictions` requires a response verb nearby | broad keyword match | Benign text like "a kingdom with no rules" must pass; the classifier handles subtler attacks | yes |
| Pipeline order kept as Rules → Classifier → PII | PII first | Tested: the classifier false positive on "remember X for later" persists after redaction, so reordering wouldn't help | yes |
| Root span from FastAPI auto-instrumentation, then `gateway.request` → `step.<name>` spans; ASGI receive/send spans excluded | manual spans only | One clickable trace per request with the HTTP span on top; receive/send spans add noise without information | yes |
| Verdict, scores, cost, tokens as span attributes (`bulwark.*`) | span events, logs | Searchable in Jaeger (e.g. `bulwark.verdict=blocked`) | yes |
| Prometheus `blocks_total` reason label = rule id or layer name | free-text reason | Keeps label cardinality bounded | yes |
| Grafana dashboard generated from `observability/grafana/build_dashboard.py` (JSON committed) | hand-edited JSON | Python is reviewable in a minute; JSON is still what Grafana provisions | yes |
| Pinned images: collector-contrib 0.165.0, Jaeger 2.23.0, Prometheus v3.16.0, Grafana 13.2.5 | `latest` | Reproducible `docker compose up` | yes |
| Collector exporter `otlp_grpc` (not `otlp`) | `otlp` | `otlp` alias is deprecated in collector 0.165 | yes |
| Classifier + spaCy model baked into the image (3.3 GB) | mount `./models` at runtime | A stranger can `docker compose up` with no setup step; BuildKit cache mount keeps uv's cache out of the image (was 4.85 GB) | yes |
| Removed `onnx` dependency | keep | Only needed for quantization, which was rejected | yes |
| Eval datasets: `deepset/prompt-injections` (Apache-2.0), `Lakera/gandalf_ignore_instructions` (MIT), `TrustAIRLab/in-the-wild-jailbreak-prompts` 2023-12-25 (MIT, sampled 300), `HuggingFaceH4/no_robots` (CC-BY-NC-4.0, 1,000 benign first-user messages) | `jackhhao/jailbreak-classification`, `xTRam1/safe-guard-prompt-injection`, alpaca, dolly | Excluded everything in the classifier's training list (jackhhao, Salad-Data, open-instruct (contains dolly), …) to avoid testing on training data. no_robots is human-written and not in the list. Licenses OK for a non-commercial portfolio eval | yes |
| Holdout = 30 hand-written attacks + 30 adversarial "near-miss" benign prompts | attacks only | The plan asked for attacks; near-miss benign prompts ("How do I enable developer mode on Android?") measure what the public benign sets can't | yes |
| **Eval v1 → rules fix (transparency note).** v1 run: rules-only R=36.8% / FPR 0.0% on public sets; combined R=84.3% / FPR 0.4%; holdout recall 93.3%; holdout near-miss FPR 20.0% (rules 13.3%, classifier 6.7%). Fixed 3 rule design bugs it exposed (`admin_override` matched the word "on", bare "developer mode", "the original instructions") with general tightening, plus regression tests | leave rules as-is | The bugs were real and would hit users; but after this the near-miss holdout is no longer fully blind *for the rules layer*. Numbers in `eval/results` are post-fix; v1 numbers are kept here | yes |
| Headline latency = p95 on **benign** prompts; all-prompt latency also reported | all prompts | Attack sets include 8K-character jailbreaks that need several classifier windows; normal users never send those. Both numbers are in results.md | yes |
| Cost per 1K assumes 150-token system prompt + 300 output tokens, 20% attack mix, $0.000024/vCPU-s for guard compute | measure with real API | No API key during build; assumptions are listed in results.md and are constants at the top of `eval/run_eval.py` | yes |
| Playground "hidden injection in an email" example uses a phishing-style payload | forward-the-inbox payload | The forward-inbox variant scored only 0.20 (a real miss, see limitations); the demo button should show the classifier catching something | yes |
| Classifier latency is length-bound, not thread-bound: ~35 ms at 32 tokens, ~120 ms at 128, ~490 ms at 400, ~715 ms at 512 on this laptop; `intra_op_num_threads` 0/4/8 made no difference | tune threads, shorter windows, distilled model | Logged as a finding instead of tuning further. Typical prompts are short (p50 guards 39 ms). Options for later: ORT transformer optimizer / a distilled model / GPU (see QUESTIONS) | yes |
| Chart series palette cyan `#0C93CF` / orange `#D95926` / violet `#9085E9` (one color per config across all charts) | UI accent `#38BDF8` + status colors | UI colors sit above the dark-mode lightness band for chart marks, and green/amber/red are reserved for verdicts. This trio passes a colorblind-safety validator against the panel color `#131A26` | yes |
| Inter + JetBrains Mono TTFs bundled in `assets/fonts/` (OFL, licenses included) | rely on system fonts | Charts and the diagram render identically on any machine; the diagram SVG embeds them | yes |
| Abuse limits (`RATE_LIMIT_RPM`, `MAX_INPUT_CHARS`, `DAILY_SPEND_CAP_USD`) implemented in `gateway/limits.py`, off by default | config-only (platform features) | A spend cap needs app knowledge (cost per request); keeping it in-app makes the deploy config portable across Cloud Run / Fly | yes |
